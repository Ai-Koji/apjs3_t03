# Привет

Цель на сегодня - научиться создавать веб - приложение на языке JavaScript с использованием среды `Node.js` и фреймворка `Nest.js`.

*__Веб-приложение__*— это программное приложение или сервис, доступный через веб-браузер, которое обычно взаимодействует с пользователем посредством веб-интерфейса. Веб-приложения обладают динамическим содержимым и могут предоставлять различные функции, такие как обработка данных, совместная работа, обновление в режиме реального времени и другие формы взаимодействия.

# Темы

- Node.js

# Задачи

Для выполнения заданий необходимо использовать актуальную версию `NodeJS` и `NestJS`. А также `IDE`, например `VSCode`

Проект создаётся один раз и используется для всех последующих заданий.

## Задание 0. Создание проекта и установка зависимостей

- Если, у вас ещё не установлен `NodeJS` или `NestJS`, то небходимо
  - Установить `Nodejs`, можно воспользоватся специальным менеджером `nvm` или скачать с официального сайта.
  - Установить `Nestjs`, необходимо в терминале ввести команду `npm i -g @nestjs/cli`.

- Выбрать каталог для хранениия проекта.

- Войти через терминал в этот каталог и создать проект с помощью командной строки nest: `nest new tic-tac-toe-api`.

- Запуск осуществляется согласно установленной конфигурациии запуска в `package.json`, например `npm start` или `npm run start:dev`,

## Задание 1. Создание структуры проекта

- Структура проекта должна иметь следующую архитектуру:  modules (модули), models (модели), services (сервисы), контоллеры (controllers), а также включать следующие слои: web, domain, datasource.

- Каждый слой является отдельным модулем

- Каждый модуль может содержать другие модули

- Слой domain должен включать в себя как минимум model, service для реализации бизнес-логики приложения.

- Слой datasource должен включать в себя как минимум model, repository, mapper для реализации работы с данными (например, с базой данных).

- Слой web должен включать в себя как минимум model, controller, mapper для взаимодействия с клиентом.

## Задание 2. Реализовать domain слой

- Описать модель игрового поля в виде целочисленной матрицы.
- Описать модель текущей игры, у которой есть UUID и игровое поле.
- Описать интерфейс сервиса, у которого есть методы:
  - Метод получения следующего хода текущей игры алгоритмом Минимакс.
  - Метод валидации игрового поля текущей игры (проверить, что не изменены предыдущие ходы).
  - Метод проверки окончания игры

- Модели, интерфейсы, реализации должны находиться в разных файлах.

## Задание 3. Реализовать datasource слой

- Реализовать класс-хранилище для хранения текущих игр.
- Описать модели игрового поля, текущей игры.
- Реализовать мапперы domain<->datasource.
- Реализовать репозиторий для работы с классом-хранилищем, у которого есть методы:

  - Метод сохранения текущей игры.
  - Метод получения текущей игры.

- Создать класс, реализующий интерфейс сервиса и принимающий в качестве параметра репозиторий для работы с классом-хранилищем.
- Модели, интерфейсы, реализации должны находиться в разных файлах

## Задание 4. Реализовать web слой

- Описать модели игрового поля, текущей игры.
- Реализовать мапперы domain<->web.
- Реализовать контроллер, имеющий метод POST /game/{UUID текущей игры}, который отправляет текущую игру с обновленным игровым полем пользователем и получает в ответ текущую игру с обновленным игровым полем компьютером.
- Если отправлена некорректная текущая игра с обновленным полем, должна вернуться ошибка с описанием.
- Должна быть поддержка нескольких игр одновременно.
- Модели, интерфейсы, реализации должны находиться в разных файлах.

## Задание 5. Регистрация модулей и запуск приложения

- Зарегистрировать модули (слои) в глобальном модуле
  - Определите параметры для импорта и экспорта
  - Опишите настройку маршрутизации
  - Определите запуск приложения
